# Lucky draw — setup & verification

Digital tickets. Buy **online by UPI** or **cash at a counter**. Each ticket gets a unique
number generated by the backend; a designed PDF ticket (name + number) is emailed to the
buyer. Winners are drawn **live on stage** from every sold, confirmed ticket.

Same Master sheet, same Apps Script as donations — one new tab (`LuckyDraw`) and a hidden
`_Counters` tab for the running numbers.

---

## What it costs

Nothing. UPI is zero-MDR; the emails and PDF tickets are generated free in Apps Script.

## Staff access

The counter is not open — you log in with a **username** (on the staff list) plus a
shared **desk key**. Every ticket / cash gift is recorded under that username, and the
hidden **`_Log`** tab keeps a full audit trail (logins, tickets, cash, winners, with
timestamps).

- **`Staff` tab** — `Username · Name · Role · Active · Notes`. Add a row → that person
  can log in. `Role` is `counter` or `admin` (admin can also run the draw). Set `Active`
  to `No` → locked out immediately. `_selfTest` seeds an admin row `roonah` / Roonah.
- Or, if you'd rather keep the list out of the sheet: put it in a **`STAFF_JSON`** script
  property — `[{"user":"roonah","name":"Roonah","role":"admin"},{"user":"priya","name":"Priya S","role":"counter"}]`.

## Script properties

Add in **Project Settings ▸ Script properties**:

| Property | Value |
|---|---|
| `COUNTER_KEY` | the shared **desk key** staff type to log in — e.g. `vim26-desk-2K26` |
| `ADMIN_KEY` | fallback secret for the on-stage draw (optional — an `admin` staff login also works) |
| `LD_PRICE` | ticket price in rupees, e.g. `50` |
| `LD_MAX` | max tickets per **online** buyer (default 25) |
| `ENABLE_EMAIL_RECONCILE` | `yes` to turn on the optional auto-confirm from bank-alert emails |
| `RECONCILE_LABEL` | the Gmail label your bank alerts get filtered to, e.g. `vim-bank-alerts` |
| `BANK_SENDER` | only trust alerts from this address, e.g. `alerts@icicibank.com` (comma-separate for more) |

### Optional: auto-confirm from bank alerts

Only if your bank sends an **email** for every credit:

1. Turn on email alerts for received/credit transactions in ICICI net-banking or iMobile.
   (SMS-only? Use an SMS-to-email forwarding app pointed at the same Gmail.)
2. In the Apps Script account's Gmail, create a filter: `from:(alerts@icicibank.com)` →
   **Apply label** `vim-bank-alerts` (and optionally "Skip inbox").
3. Set `ENABLE_EMAIL_RECONCILE=yes`, `RECONCILE_LABEL=vim-bank-alerts`,
   `BANK_SENDER=alerts@icicibank.com`.
4. The 15-minute `houseKeeping` trigger runs the match. To go faster, add a separate
   time trigger on `reconcileFromEmail` every 5 minutes.
5. **Send me one real alert email** so the amount/UTR regex can be tightened to ICICI's
   exact wording — the generic version works but a tuned one matches more.

## Redeploy

1. Paste the current `apps-script/Code.gs`, **Save**.
2. The `LuckyDraw` tab gains a `Donor UPI ref` column (added at the end) — the script
   repairs the header automatically on the next call, no need to delete the tab.
3. **Deploy ▸ Manage deployments ▸ ✏️ ▸ Version: New version ▸ Deploy.**
4. Run **`_selfTest`** → recreates `Donations` + `LuckyDraw` with the right columns and a
   hidden `_Counters` tab.
5. Config `years/2026.config.js`: `api` is already set; edit `luckyDraw.price` / `.prizes` /
   `.blurb` for the copy shown on the site (the *real* price is `LD_PRICE`).

## The two ways to buy

### Online (`draw.html`)
`drawPledge` → creates N `Pending` rows sharing one `Reference` → returns a `upi://pay`
link → buyer pays → taps "I've paid" → **enters their 12-digit UPI reference (UTR)** →
rows go `Paid?` with that UTR saved in the `Donor UPI ref` column.

**Confirming the payment** (any of these — pick what suits you):

1. **Staff desk → "Confirm UPI" tab.** When you see the money land in your bank app,
   open the desk on your phone, paste the same UPI reference, tap **Confirm payment**.
   The script finds the matching `Paid?` row(s), confirms the whole reference, issues the
   ticket numbers, emails the PDF, and logs who did it. *This is the quick everyday path.*
2. **In the sheet.** Filter `LuckyDraw` to `Status = Paid?`; each row shows the buyer's
   name, amount and their UPI reference. Cross-check against the bank statement, set
   **one row** of a reference to `Confirmed` → the whole reference confirms and emails.
3. **Automatic (optional).** If your bank emails you a credit alert for every payment,
   forward those to the Apps Script Gmail, label them, and set the three script
   properties below. A trigger then matches `UTR + amount` and confirms automatically.
   Anything it can't match just waits for path 1 or 2.

Buyers who genuinely can't find their reference tap "I can't find my reference number" —
their row still becomes `Paid?` (no UTR), and you confirm it by hand against the statement
by end of day.

### Cash counter — the "Staff desk"
The counter is **built into every money page**. On `draw.html` and `donate.html` there's a
small **"Staff desk"** link in the footer; `counter.html` is the same thing full-screen.

A volunteer taps it, enters their **username + the desk key** (`COUNTER_KEY`) **once** — it
stays logged in across all the money pages for that browser session (`sessionStorage`),
and everything they do is recorded under their username. Then, on any of them:

- **Lucky Draw** tab: quantity, **buyer name + phone (required)**, email (optional) →
  **Issue tickets** → `drawIssueCash` → numbers generated **immediately**
  (`Channel = Cash`, `Status = Confirmed`), shown big, emailed if an address was given.
- **Cash Donation** tab: amount + name → **Record** → `donateCash` → a Confirmed donation row.

A running **"N sales · ₹X to hand over"** bar tracks the shift for end-of-day cash
reconciliation. **End shift** clears it.

Give volunteers any of these + the shift key:
`https://vimusement.github.io/2026/counter.html` (dedicated) or just the normal
`draw.html` / `donate.html`.

## Verifying — in order

Use real ₹1 UPI / small cash. `LD_PRICE` can be set to `1` for testing, then back to `50`.

| Step | Do | Expect |
|------|----|--------|
| **V1** | `<api>?action=ping` and `?action=drawInfo` | `{ok…}` and `{"price":..,"maxOnline":..}` |
| **V2** | `?action=staffLogin&user=roonah&k=<COUNTER_KEY>` | `{"ok":true,"name":"Roonah","role":"admin","token":"…"}`. Wrong key → `{"error":"Desk key not recognised"}`; unknown user → `{"error":"That username isn't on the staff list"}` |
| **V3 online** | On `draw.html`: 2 tickets, name + email + phone → Continue → pay → "I've paid" | 2 `Pending`→`Paid?` rows in `LuckyDraw`, same Reference, no Ticket ID yet |
| **V4 confirm** | Set **one** of those rows' Status → `Confirmed` | both rows become `Confirmed`, both get a `LD-2026-000x` number, and the buyer gets an email with a **PDF ticket** attached |
| **V5 counter** | `counter.html` (or "Staff desk" on any money page) → username + desk key → Lucky Draw → qty 1, buyer name + phone → Issue | a number shows on screen instantly; a `Cash` / `Confirmed` row appears with that number and your username in `By`; a line appears in `_Log`; shift total updates |
| **V6 counter cash donation** | Cash Donation tab → ₹1, name → Record | a `Cash` / `Confirmed` donation row + `_Log` line; supporters wall picks up the name (if ticked) |
| **V7 access control** | log in with a username **not** on the Staff list, or a wrong desk key, or a user whose `Active` = `No` | rejected — can't get in |
| **V8 pool** | `?action=drawPool&k=<ADMIN_KEY>` | `{"pool":[{id,name}…],"count":N}` — every confirmed ticket, winners excluded |
| **V9 stats** | `?action=drawStats` | `{sold, amount, pool}` |

## The draw — `stage.html`

On the night, open **`stage.html`** on the MC's laptop and put it on the projector.

1. Log in with an **admin** username + the desk key (your `roonah` row).
2. The ticket pool loads — "*N tickets in the hat*".
3. Pick the prize from the dropdown (from `luckyDraw.prizes`, or "Custom…").
4. **Draw** → the number spins and lands on a random ticket, with confetti and the
   holder's first name.
5. **Confirm winner** → records it in `LuckyDraw` (`Won` column), logs it, and emails the
   winner. The dropdown advances to the next prize.
6. **Next prize →** reloads the pool (the winner is now excluded) and you draw again.

Manual fallback if the screen won't cooperate: `?action=drawPool&token=<admin token>` (or
`&k=<ADMIN_KEY>`) lists the pool; record a winner with
`?action=drawRecordWinner&k=<ADMIN_KEY>&id=LD-2026-0012&prize=1st%20prize`.

## Notes

- **Buyer phone is required** everywhere — it's the backup contact if a winner's email
  bounces.
- The PDF ticket uses email-safe fonts (Georgia / Helvetica / Courier). If the Apps Script
  PDF renderer is unavailable for any reason, the email still goes out with the numbers in
  the body — just no attachment.
- One PDF per purchase, one ticket per page.
- `_Counters` tab: never edit by hand. If you must reset numbering, set the `LD` value to
  the last-issued number.
